# Localization Foundation

Stemma localization is workspace-aware and server-first. Product pages should call the runtime dictionary loader on the server and pass resolved strings, or a narrow dictionary, into client components. Do not add a global client-side translation store for normal page rendering.

## Data Model

The Prisma localization models are:

- `Locale`: workspace-owned locale code, display name, enabled flag, and default flag.
- `TranslationKey`: stable namespaced key metadata such as `shell.nav.dashboard`, default Russian text, English seed text, description, and owner area.
- `TranslationValue`: workspace and locale-specific draft and published text, publisher, published time, and version.
- `TranslationAudit`: append-only history for create, draft, publish, and rollback actions.

`Workspace` owns locales, values, and audits. `User` is linked to published values and audit actions.

## Runtime Fallback

`getDictionary(workspaceId, requestedLocale)` returns published values only. Drafts are intentionally ignored outside the admin editor.

Fallback order:

1. Exact requested enabled workspace locale.
2. Base language enabled workspace locale, for example `en` for `en-US`.
3. Workspace default enabled locale.
4. Built-in dictionary fallback: requested locale, base language locale, then built-in `ru` as implemented.
5. The translation key itself.

This means missing database rows must not break product pages. A workspace can enable a regional locale before every key has a published override, and the runtime will still render from built-ins or keys.

## Admin Editor

The online localization editor lives under admin localization routes. Admins can create arbitrary BCP-47-style locale codes, enable or disable locales, filter keys, edit drafts inline, publish a draft, roll back from audit history, and inspect audit entries.

Draft text is visible only in the admin editor. Product UI must use `publishedText` values only.

## Contributor Rules

- Add new product strings as stable namespaced keys, not as ad hoc database rows.
- Keep keys semantic and area-owned, for example `dashboard.focus.title`.
- Seed Russian and English built-ins for new keys.
- Keep Prisma out of middleware/proxy code. Workspace database dictionaries are for server components, route handlers, and server actions.
- Treat missing translations as normal operational state, not as a page error.
