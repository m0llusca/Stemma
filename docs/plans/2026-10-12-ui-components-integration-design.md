# Stemma: применение неиспользуемых UI-компонентов

Статус: вариант A утверждён пользователем 12 октября 2026. OTP отложен; next-themes удаляется.
Основа: актуальный `master` `a11a43a`; обычный CI и verify-DB smoke этого коммита успешны. План реализации: `2026-10-12-ui-components-implementation.md`.

## Цель

Улучшить действующие сценарии QA, отчётов, обучения и настроек с помощью уже установленных компонентов. Сохранить русскую локализацию, права доступа, серверные действия, URL-фильтры, темы, Recharts и существующие ограничения JavaScript. Новые страницы с демонстрацией компонентов и искусственные функции ради счётчика использования не добавляются.

## Подходы

**Рекомендуемый вариант A:** подключить 14 компонентов к существующим пользовательским сценариям. `InputOTP` оставить до появления настоящего сценария одноразового кода. Использовать `react-day-picker` и `react-resizable-panels`; удалить неиспользуемый `next-themes`, сохранив текущий механизм appearance.

## Размещение компонентов

| Компонент | Место | Пользовательский результат |
|---|---|---|
| `alert-dialog` | Общий `ConfirmSubmitButton`, используемый отзывом токенов, удалением расписаний и отменой заданий | Доступное подтверждение с понятным последствием, отменой и возвратом фокуса вместо browser confirm |
| `aspect-ratio` | Существующие previews оформления в настройках | Согласованные пропорции и стабильный размер предпросмотров |
| `avatar` | Меню текущего пользователя и идентификация операторов в коучинге | Единый аватар с инициалами, без выдуманных фотографий и внешних запросов |
| `breadcrumb` | Вложенные страницы: интеграция, задание системы, отдельная калибровка, обращение | Понятный путь к родительскому разделу; возврат в очередь сохраняет её фильтры |
| `calendar` | Пользовательский период отчётов | Выбор диапазона на русском, сохранение ручного ввода и явное применение полного диапазона |
| `combobox` | Длинные списки операторов/проверяющих в фильтрах очереди | Поиск внутри существующих вариантов без изменения значений фильтра и его URL-контракта |
| `hover-card` | Дополнительная справка по QA-критериям | Быстрый preview; существенные инструкции остаются доступными в основной карточке и на touch/для screen reader |
| `item` | Списки существующих заданий обучения | Единая композиция заголовка, статуса, срока и действий |
| `menubar` | Группы действий отчёта: представление, фильтры, экспорт | Клавиатурная навигация по действиям, сохранение канонических фильтров экспорта |
| `navigation-menu` | Навигация подразделов настроек | Единые ссылки и активное состояние с прежними проверками прав |
| `progress` | Существующий прогресс плана коучинга | Замена собственного progressbar на общий компонент; значения только из реальных done/total |
| `resizable` | Desktop workbench проверки: разговор и форма оценки | Изменяемая ширина панелей, сохранение локальной раскладки; на мобильных сохраняется однопанельный режим |
| `scroll-area` | Длинные desktop-панели workbench | Прокрутка длинного разговора и формы, сохранение переходов к evidence и клавиатурного фокуса |
| `slider` | Существующее поле «Доля, %» правила выборки | Регулировка 1–100% совместно с точным числовым вводом; один `targetPercent` в FormData |
| `input-otp` | Будущий настоящий OTP-сценарий входа/подтверждения | Подключение только вместе с реальной серверной функцией; в A не используется |

## Зависимости

- `react-day-picker` 10.0.1 используется через имеющийся `Calendar`; совместимость проверяется по установленной версии. Дни в URL остаются календарными датами, без сдвига из-за UTC-преобразования.
- `react-resizable-panels` 4.12.2 используется через имеющиеся wrappers `Group`/`Panel`/`Separator`; проверяются клавиатурное изменение ширины, минимальные размеры и стабильная гидратация.
- `input-otp` остаётся в A вместе со своим неиспользуемым wrapper; одноразовые коды в текущем backend отсутствуют. Его наличие не означает наличие MFA.
- `next-themes` предлагается удалить: существующий `syncUiAppearanceToDocument` уже синхронизирует тему, плотность, скругления, контраст, dark-класс, color scheme и CSS-переменные. Второй источник состояния не нужен для перечисленных улучшений.
- UI-компоненты продолжают композицию shadcn/Base UI `base-nova`; CLI shadcn не возвращается в dependencies.

## Поведение и границы

1. AlertDialog подтверждает исходную форму ровно один раз через её submitter; HTML validation, name/value кнопки, FormData и серверная авторизация сохраняются. Отмена не вызывает action.
2. Combobox сохраняет исходные значения вариантов. Одинаковые отображаемые имена не становятся идентификаторами там, где исходный контракт использует ID.
3. Calendar не применяет незаконченный диапазон. Отмена сохраняет прежние значения. Team/source/risk/block, период и сравнение сохраняются в ссылках/экспорте.
4. Resizable и ScrollArea не меняют роли проверки, закреплённую методику, черновик, evidence и переход «Взять следующий». Минимальные размеры не позволяют скрыть форму. На узком экране нет обязательного desktop-разделителя.
5. Progress не изображает выдуманный процент импорта: текущие jobs не имеют достоверного total. Для плана без задач отображается явное отсутствие заданий.
6. Большие необязательные элементы загружаются локально на нужных маршрутах/при открытии. SSR-каркас, фокус и доступность остаются рабочими.
7. Все графики остаются на Recharts. Baseline и числовые пределы бюджетов не увеличиваются, полный rich-chart предел остаётся 70 KiB.

## Приёмка и отправка

- TypeScript, полный unit/API-набор, изолированный PostgreSQL и production build.
- Регрессии: confirmation cancel/submit-once/validation; combobox FormData/clear/search; calendar apply/cancel/date boundaries; slider exact value; resize keyboard/persistence/mobile; реальные значения progress.
- Browser QA: основные роли, настройки, отчёты, workbench/evidence, светлая/тёмная тема, reduced motion и forced colors. Axe без critical/serious в затронутых сценариях.
- Полный `npm audit` без уязвимостей; существующие JS-бюджеты проходят без переснятия baseline по изменённому результату.
- Обновлённая инвентаризация показывает реальные подключения. В A остаётся один намеренно отложенный `input-otp`, а не ложное «используются все 15».
- После согласования и выполнения: commit/push в `master`, обычный GitHub CI и расширенный verify-DB smoke на итоговом SHA. Разрешение на эти действия уже дано пользователем; повторно запрашивать его не требуется.
