# Повторная проверка Stemma и применение UI-компонентов

Основа: `master` `a11a43a`. Вариант A утверждён пользователем; OTP отложен. Проверки этой версии перечисляются ниже после завершения, отдельно от предыдущего аудита.

## Действующий UI

Проект использует исходники shadcn/ui с Base UI 1.9 (`base-nova`), Tailwind v4, Lucide/Morphicons, Sonner, cmdk, Recharts, react-day-picker и react-resizable-panels. Тема управляется существующим appearance-механизмом Stemma; неиспользуемый next-themes удалён. Все графики сохранены на Recharts.

Инвентаризация: 197 компонентных файлов — 75 общих UI и 122 доменных. В runtime-граф приложения входят 74 из 75 UI-файлов; исключение — отложенный InputOTP.

Подключены 14 компонентов к существующим задачам:

| Компонент | Использование |
|---|---|
| AlertDialog | Подтверждения удаления, отзыва и отмены; исходный submitter и HTML validation сохранены |
| AspectRatio | Предпросмотры оформления |
| Avatar | Инициалы пользователя и операторов |
| Breadcrumb | Вложенные интеграции, задания, калибровки и проверки |
| Calendar | Русский выбор диапазона отчёта с ручным вводом и Apply/Cancel |
| Combobox | Поиск по длинным спискам операторов/проверяющих в очереди |
| HoverCard | Дополнительная справка по критериям; основные инструкции остаются inline |

| NavigationMenu | Навигация настроек с прежними ограничениями ролей |

| ScrollArea | Длинные панели разговора и оценки |
| Slider | Доля выборки 1–100%, совместно с точным числовым полем |

Удалены устаревшие `MasterDetail` и `ReportDateInput`, заменённые действующими компонентами. `InputOTP`/input-otp намеренно остаётся единственным отложенным UI-компонентом: серверного OTP-сценария пока нет. Новые функции ради использования зависимости не добавлены. Дальнейшее подключение OTP требует полноценного серверного протокола выдачи/проверки/лимитов.

Дополнительно проверены зависимости вне UI. `date-fns` используется транзитивно Calendar через react-day-picker. YDB, SAML, LDAP и PDFKit имеют действующие серверные потребители; их отсутствие в клиентском bundle не означает неиспользование. У `superjson` прямых runtime-потребителей сейчас нет: существующие формы/URL/экспорты не требуют нового протокола сериализации. Встраивать его только ради использования было бы лишней сложностью; это кандидат на отдельное удаление, а не новая продуктовая функция.

Актуальная [инвентаризация](2026-10-12-ui14-inventory.json) построена по runtime-import/re-export/literal dynamic import из Next entry points. Она показывает достижимость исходников, а не размер браузерной загрузки и не доказательство выполнения каждой ветви.

## Найденные и исправленные дефекты

1. Неподписанная cookie `qc_current_user_id` позволяла выбрать пользователя без проверки сессии. Этот путь и выдача cookie удалены; ошибочные credentials не запускают локальный fallback.
2. Ранее выданные DEMO-сессии могли пережить отключение demo-входа через Auth.js. Оба читателя сессий теперь применяют общий ACTIVE/expiry/provider/workspace gate.
3. Фоновые экспорты теряли team/source/risk/block. Используется общий список поддерживаемых фильтров; значения проходят проверку и тот же загрузчик, что интерактивный экспорт.
4. Изменение статуса ранее назначенного учебного задания не проверяло актуальное право обучения. Проверка выполняется до транзакции; ограничение собственного задания сохранено.
5. Завершение/архивация калибровки конкурировала с записью оценки. Разделяемая блокировка строки сессии удерживается до commit оценки; статус повторно читается после получения блокировки.
6. Ошибка транспорта уведомлений возвращалась как успешное завершение job. После обработки каналов job сообщает ошибку, включая штатные ограниченные retry/backoff; уже доставленные каналы дедуплицируются.

При браузерной проверке дополнительно исправлены: приоритет скрытия мобильной Resizable-панели над inline display; перенос фокуса к evidence-сообщению и устранение перехвата Enter на ссылке; прокрутка длинной формы с календарём внутри мобильного Sheet и desktop Popover; неактивная SSR-кнопка административного диалога до гидратации.

Первый CI выявил гонку фокуса при переходе из меню сохранённых отчётов в диалог: завершение закрытия меню могло вернуть фокус на его кнопку. Передача фокуса теперь явно задаётся публичным `finalFocus`, без таймеров. Регрессионный тест дожидается удаления DOM-узла меню, проверяет сохранение фокуса в поле, ввод, Tab/Shift+Tab, Escape, возврат к исходной кнопке и отсутствие POST при отмене. Он включён в verify-DB smoke.

Base UI обновлён с 1.6 до 1.9.0. Весь Menubar Portal вынесен за пределы DOM Menubar через публичный ReactDOM portal, сохраняя React-контекст и порядок фокуса. Нулевой размер применяется только к aria-hidden guards. Для открытых VoiceOver-кнопок сохраняется исходная геометрия и добавляется настоящее aria-label в обоих модульных форматах Base UI. Узкий postinstall-скрипт проверяет точную версию и SHA-256 исходных/пропатченных файлов; неизвестный артефакт блокирует установку до проверки. Повторный запуск идемпотентен, дополнительных зависимостей не требуется. Команды отчёта используют nonmodal-политику. Axe critical/serious не отключаются; проверяются реальные Tab/Shift+Tab/Escape и возврат фокуса.

Измеритель JS-бюджетов теперь распознаёт настоящие вызовы загрузчика Turbopack по AST и контексту module factory, а не любой метод `.l()`. Неизвестные настоящие загрузчики по-прежнему блокируют проверку. Общие числовые токены Kinetics вынесены в `@stemma/kinetics/durations`; канонические значения и CSS-синхронизация сохранены. Это уменьшает ненужную связь графиков с общими UI-экспортами.

## Проверка

- Чистый npm ci, полный npm audit (0 уязвимостей), typecheck и production build прошли на Node 24.
- Unit/API: полный набор и целевые повторы после исправлений — 3018 проверок; отдельные тесты проверяют чистое применение, идемпотентность и отказ патча при неизвестной версии/содержимом зависимости.
- PostgreSQL: существующие 20 тестов прошли; новые 8 гонок калибровки прошли отдельно вместе с очисткой.
- JS-бюджеты: shared 324885 B; reports 373759 B; dashboard 429779 B; coaching 350088 B; полный rich-chart 63169 B при неизменном лимите 71680 B. Измеряется вся физическая цепочка, а не только дополнительная загрузка графиков.
- Браузеры: 8 новых UI-сценариев проверены в Chrome, Firefox и WebKit; найденные регрессии повторно проверены после исправлений. Axe сохраняет полный набор правил и выполняется после завершения конечных анимаций, чтобы проверять стабильные цвета.
- Workbench: проверены 390/768/900/1280/1440 px, сохранение ширины и клавиатурный переход к evidence. Дополнительно проверены основные маршруты/роли, темы, reduced motion, forced colors и загрузка графиков.
- Подтверждение через реальный Next server action: отмена без мутации/POST; подтверждение — один POST и одна запись immutable audit.
- Выгрузки используют обычные ссылки на attachments: открытие меню не вызывает prefetch, CSV скачивается одним запросом, URL отчёта сохраняется.
- GitHub CI запускается после push; ссылки на итоговые runs и SHA приводятся в сообщении о завершении.

Primary database не используется: интеграционные и браузерные проверки выполняются на `qc_app_demo_verify`. Live-сертификация внешних интеграций не выводится из локальных фикстур. Базовый snapshot и лимиты JavaScript не увеличиваются.
